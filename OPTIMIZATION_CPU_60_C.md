# CPU Optimization Ledger: Batch C

This ledger records the third batch of CPU-focused optimizations. The source
of truth is the `.gd.part` file named in each row; `scripts/main.gd` is
assembled output.

| # | File / function | Previous hotspot | Optimization | Verification |
|---:|---|---|---|---|
| 70 | `core.gd.part` / `can_form_sets_with_memo` | Every recursive set-formation state rescanned tile counters from slot zero. | Pass the current first candidate slot into recursive calls and scan only the remaining suffix. | `performance_optimization_60_c_check.gd`, `ai_play_round25_check.gd` |
| 71 | `ai_brain.gd.part` / `hand_plan_features_from_counts` | Each repeated route evaluation rescanned all 34 counters and rebuilt the feature dictionary. | Add a bounded linked-list LRU keyed by count vector and explicit tile total; return isolated copies to callers. | `performance_optimization_60_c_check.gd`, `ai_play_round87_check.gd`, `ai_play_round97_check.gd` |
| 72 | `ai_brain.gd.part` / `opponent_pressure_score` | Discard and gang paths recomputed the opponent loop after pressure context construction. | Reuse the seat-matched `opponent_pressure` value already present in the evaluation context. | `performance_optimization_60_c_check.gd`, `ai_play_round80_check.gd` |
| 73 | `core.gd.part` / `full_straight_suit_from_counts` | Each candidate suit rescanned every open meld to find 123/456/789 groups. | Classify each eligible open meld once, then reuse the three-suit group table. | `performance_optimization_60_c_check.gd`, `ai_play_round25_check.gd` |
| 74 | `ai_brain.gd.part` / `opponent_readiness_pressure_score` | Readiness pressure was recomputed across every opponent when an evaluation context already held the pressure context. | Reuse the seat-matched cached `readiness_pressure` value and retain the live scan as a fallback. | `performance_optimization_60_c_check.gd` |
| 75 | `render.gd.part` / hand tray decoration | Suit-flow and completion-bus art independently regrouped the same hand during one render. | Compute the five group counts once in `draw_hand` and pass the snapshot to both decoration builders. | `ui_layout_smoke_test.gd` |
| 76 | `ai_brain.gd.part` / `opponent_readiness_pressure_score` | Context-free calls rebuilt opponent plan pressure for every invocation. | Populate and reuse the existing state-keyed opponent runtime snapshot before falling back to context-aware evaluation. | `performance_optimization_60_c_check.gd`, `ai_play_round80_check.gd` |
| 77 | `gameplay.gd.part`, `render.gd.part` / discard river grids | Every battle redraw recreated four grid containers and all visible discard tile controls. | Retain grids across battle redraws and reuse them only when river content, window, geometry, mode, and highlight signatures match; release stale grids immediately. | `performance_optimization_60_c_check.gd`, `ui_layout_smoke_test.gd` |

| 79 | `main_base.gd`, `core.gd.part` / compact shanten keys | Every recursive memo-key lookup allocated a fresh byte buffer before converting the 34 counters to a string. | Reuse one script-level scratch buffer while retaining the returned immutable string keys. | `performance_optimization_60_c_check.gd`, `offline_smoke_test.gd` |
| 80 | `ai_brain.gd.part`, `core.gd.part` / winning wait valuation | Each wait candidate rebuilt and normalized the full simulated hand before scoring it. | Reuse the discard evaluator's 34-slot count snapshot and score winning candidates through the count-based API; retain the array path for legacy callers. | `performance_optimization_60_c_check.gd`, `ai_play_round80_check.gd`, `ai_play_round96_check.gd`, `ai_play_round97_check.gd` |
| 81 | `ai_brain.gd.part` / `build_ai_claim_report` | A context-free claim report evaluated the same seat-aware hand plan once for the decision score and again to read its bonus. | Reuse the already computed `before_plan_report` for `plan_bonus`, removing one full feature/report rebuild per standalone claim evaluation. | `ai_play_round3_check.gd`, `ai_play_round10_check.gd`, `performance_optimization_60_c_check.gd` |

| 83 | `gameplay.gd.part`, `render.gd.part` / meld lanes | Every battle redraw recreated each populated meld lane, its group tile views, badges, lane art, and optional pager. | Retain the complete per-seat meld lane subtree and reuse it only when meld order/content, page window/capacity, safe-area geometry, compact mode, and visual settings match; stale lanes are released with the render retention set. | `performance_optimization_60_c_check.gd`, `ui_layout_smoke_test.gd` |

The ledger describes bounded work and reuse; it does not claim a benchmark
