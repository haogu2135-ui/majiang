## 当前功能

- 横屏 Godot UI。
- 麻将牌面使用既有纯 2D 资源，复用桌布、木纹、音效素材及 Godot 专用花牌 PNG。
- 单机模式：本地发牌、自动补花、三家 AI 自动行牌，三家电脑分别带有守门清、速攻和做大牌的稳定性格权重，出牌、防守、吃碰杠和自杠取舍会按座位风格变化；支持本地吃/碰/杠/胡、自摸、荒庄、包三搭包赔、清一色/混一色/碰碰胡/字一色/大三元/小三元/大四喜/小四喜/一条龙/断幺九/杠上开花/海底捞月/河底捞鱼/大吊车/抢杠胡等番型、多局分数保留、庄家连庄/下庄、暗杠/明杠/补杠、多人可选吃牌组合、胡牌优先于碰杠吃的响应优先级、点炮多人可胡时保留玩家胡牌窗口且最终单家结算、碰杠吃同级按出牌后近家优先，以及基于向听数、有效进张、牌型潜力、对手副露威胁和防守风险的 AI 推荐出牌；AI 吃牌会逐一评估所有可吃组合，按综合收益选择具体吃法；AI 暗杠/补杠会综合向听、牌值、攻守压力、路线保护和抢杠风险后再决定是否执行。
- 联机模式：连接现有 `mahjong-room-server` JSON Lines 协议，支持创建房间、加入房间、开始、出牌、响应吃碰杠胡入口，联机吃牌可显示并发送具体吃法，兼容常见 room/game state 字段别名，并显示服务器确认、拒绝原因和房间日志。
- 牌局声音：启动、进桌、恢复前台、触摸/按钮/牌点击都会唤醒音频并重试 BGM；Android 包使用 32 kbps 移动端 MP3 曲目，避免把高码率源音频带入安装包；摸牌/出牌与碰杠胡音效复用持久播放器，快速行牌时减少节点分配和混音抖动；随包内置中文牌名和动作语音，出牌优先播放本地语音片段，不再依赖手机 TTS 初始化成功才有报牌；系统 TTS 作为兜底，设置面板提供“试音”一键重新开启并播放测试报牌。
- 设置面板：菜单和牌桌顶部可切换音乐、音效、报牌和快速模式，设置会保存到本机。
- 操作流畅度：菜单、按钮、行动区和手牌按下即执行；快速模式把 AI 计算等待和可见动作停顿分开，人出牌后、AI 杠牌后、每个 AI 出牌后都会留出短暂落桌间隔，让画面刷新、出牌音和报牌按顺序出现，避免三家 AI 声音堆到一起；BGM 已在播放时不再由后台看门狗定时重触发播放链路；帧循环只在下载、语音或联机场景进入对应轮询，联机 socket 轮询和下载进度刷新也按短时间窗节流，降低空闲帧和下载帧的主线程开销；人机对战中玩家侧 AI 辅助默认关闭，不再计算/显示推荐牌、最安牌、备选牌、风险徽标、提示按钮和响应建议；AI 连续行牌时整桌重绘合并到短刷新窗口，减少主线程卡顿；向听数、AI 出牌报告、牌序排序、牌面分类/显示名/语音名/颜色、十三幺牌面索引、UI 样式和对手威胁报告使用缓存，AI 推荐和进张候选只在收集完成后排序一次，重复牌候选先按牌面去重，每张候选弃牌只统计一次手牌计数并复用于向听、进张、形状质量、路线评分和路线报告，候选报告也可接收已扣减的手牌计数快照，常规出牌和副露后强制弃牌不再为每个候选重新 tile_counts，候选模拟复用一份工作手牌和工作计数并按牌面索引临时扣减/恢复，避免每个候选 duplicate 整手牌和计数快照；牌面计数数组统一用固定长度零填充 helper 初始化，减少高频手牌/公开牌计数里的解释器循环；出牌理由标签复用弃牌前原手牌计数快照判断七对保路线和孤张，避免每个候选再复制恢复原计数、重建原手牌数组和重新统计；AI/威胁报告缓存键使用稀疏牌面计数生成稳定牌序 key，避免每次查询都分配并填满 34 槽计数数组；AI 出牌报告写入缓存时只定向复制有效进张、剩余张数、喂牌详情和危险来源等可变字段，替代整份报告递归深拷贝；向听递归 memo key 复用单次紧凑计数键，紧凑计数键用字节缓冲生成常规 0-9 计数串，减少递归里重复小字符串数组分配；完整胡牌面子递归原地加减并使用局部 memo，避免每个分支复制计数数组；听牌价值评估在 AI 候选报告中复用已验证的有效待牌列表，跳过重复完整胡牌校验，并复用一个临时和牌手牌数组逐张 append/pop 计算待牌价值，不再为每个待牌 duplicate 手牌；同时把自家弃牌预先建成集合，判断回头待时不再反复扫描弃牌河；AI 候选弃牌一次分析番型路线、对子路线、十三幺、一条龙和听牌价值，再复用到路线评分、形状摘要和报告描述；吃碰杠响应先统计一次手牌计数，再用计数快照扣减响应牌并复用到向听、形状和路线收益，响应选项也复用同一份手牌计数判断胡/杠/碰/吃，避免同一响应反复复制手牌、count_tile 和扫描吃牌组合；同一张弃牌的 AI 吃碰杠响应会共享响应评估上下文，杠/碰/多种吃法复用手牌计数、公开牌计数、对手状态、压力上下文、风险向量和安全牌标签缓存；弃牌压力、喂牌风险、放铳风险和安全牌标签共享公开牌计数快照，筋线和壁牌安全判断直接用牌面索引、对手弃牌上下文和可见计数，不再构造锚点/壁牌临时数组，同一轮候选弃牌共享对手压力、听牌压力和威胁等级上下文，放铳总风险和最大危险来源合并为一次逐家扫描，逐家风险组件复用同一个结果字典，避免每个对手都分配组件报告，进张评估直接复用手牌计数并临时加减候选牌，常规候选出牌和副露后强制弃牌评估都共享公开牌计数、对手状态、风险向量和安全牌标签缓存，只需要风险分数的路径和威胁安牌候选排序直接读取风险向量分数，跳过中间摘要字典，威胁安牌候选只维护前 N 个轻量候选，避免为全量候选创建字典并整体排序，风险向量和喂牌报告缓存命中也只定向复制危险来源、喂牌详情等可变字段，缓存命中避免深拷贝嵌套报告，减少同一牌桌状态下提示、风险徽标、座位威胁和推荐的重复计算。
- 待牌价值性能：非听牌候选直接返回零值待牌指标，跳过攻击/待牌权重计算；AI 出牌候选报告对非听牌直接填充零值待牌字段，不再进入 `wait_value_metrics` 或读取自家弃牌 lookup，自家弃牌 lookup 也改为听牌候选按需生成；听牌候选复用 AI 出牌报告已计算的攻击倍率，避免同一候选重复读取分势和 AI 性格权重。

- 座位 UI 性能：牌桌重绘时每个对手只取一次威胁报告，座位徽标、颜色和威胁说明共用同一结果；同一次渲染中的三个对手面板共享 AI 评估上下文、风险向量和安全牌标签缓存；威胁报告缓存命中只做轻量保护性拷贝，减少手机端整桌重绘时的分配压力。

## 构建

```bash
cd /home/guhao/majiang
cp export_presets.example.cfg export_presets.cfg
QEMU_LD_PREFIX=/usr/x86_64-linux-gnu GODOT_SILENCE_ROOT_WARNING=1 godot --headless --path . --export-release Android build/YunzhuoMahjongGodot-v1.0.180-godot.apk
```

`export_presets.cfg` 是忽略提交的本机配置；首次导出从受控模板复制，release 签名信息只填入本机文件。ARM64 主机上的 Android build-tools 是 x86_64 程序，导出和 Gradle daemon 操作都需要 `QEMU_LD_PREFIX=/usr/x86_64-linux-gnu`；x86_64 主机可省略该变量。导出前可先运行 `scripts/verify_android_release.sh --toolchain-self-test`。

Android 模板使用 `scenes` 依赖过滤、单 `arm64-v8a` 架构、ETC2 纹理、移动端音频白名单和 384px 装饰图导入上限；麻将牌面与 3D 桌面材质不套用该上限。不要用 `--export-debug` 或 `all_resources` 生成发布包。当前 release 资源策略的实测 unsigned APK 目标约 96 MB，签名只会增加少量元数据；签名 release 审计默认把 125 MB 作为体积回归上限，可用 `ANDROID_RELEASE_MAX_BYTES` 调整。

Godot Android 设置：

- Java SDK Path: `/usr/lib/jvm/java-21-openjdk-arm64`
- Android SDK Path: `/opt/android-sdk`
- Export templates: `/root/.local/share/godot/export_templates/4.6.3.stable`

## 脚本结构 / 模块化

由于 GDScript 4.6 仅支持单继承且无 `#include`/mixin，`scripts/main.gd`（曾为 2.6 万行的巨型单文件）现采用「**源子模块 + 构建期拼接**」结构：

- 人类在 `scripts/main_src/*.gd.part` 分模块编辑（`audio` / `ai_brain` / `gameplay` / `render` / `screens` / `online` / `core`），`_header.gd.part` 是唯一全局头部（`extends` + `preload` + `ui_enhancements` 变量）。
- 运行 `python tools/assemble_main.py` 把各 part 按 `ORDER` 固定顺序拼成发货用的 `scripts/main.gd`（顶部带 AUTO-GENERATED 警示头）。
- 运行时仍为单一脚本，`Main.tscn` 根脚本路径不变；烟测/构建脚本按名访问的公共符号经继承可见。

| 命令 | 作用 |
|---|---|
| `python tools/assemble_main.py` | 生成 `scripts/main.gd` |
| `python tools/assemble_main.py --check` | 仅校验 part 合法性（无重复 func、无非法顶层关键字） |
| `python tools/assemble_main.py --verify` | 比对现有 `main.gd` 与生成产物是否字节一致（CI 守门） |
| `python tools/assemble_main.py --diff` | 对比现有 `main.gd` 与生成产物的 func 名集合差异 |
| `python tools/split_main_parts.py` | 调试用：打印 `core.gd.part` 的顶层块清单 |

**编辑约定：** 改 `main.gd` 行为一律改对应 `scripts/main_src/*.gd.part`，跑 `python tools/assemble_main.py` 重新生成，再运行回归闸门：

```bash
GODOT_SILENCE_ROOT_WARNING=1 godot --headless --script scripts/offline_smoke_test.gd
```

`./verify_build.sh` 已集成 `--check` / `--verify`，产物不一致会报错。

商用验收使用以下串行门禁：

```bash
scripts/verify_ai_commercial.sh
scripts/verify_ui_regressions.sh
scripts/verify_android_release.sh /path/to/YunzhuoMahjongGodot-v1.0.180.apk
scripts/verify_android_device.sh --unsigned-debug /path/to/device-test.apk
scripts/verify_online_production.sh [HOST] [PORT]
```
